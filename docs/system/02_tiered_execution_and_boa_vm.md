# `slice-engine`: Hybrid Three-Tier Execution Pipeline, `WarmBoaRealm` & Native Intrinsics

[`crates/slice-engine`](../../crates/slice-engine/src/lib.rs) is designed around a single principle: **use the lightest execution tier capable of running the workload, pay `0.00 ns` and `0 B` for unused Web/Node globals via compile-time minified lazy prelude shards, and accelerate hot standard-library primitives in native Rust**.

---

## 1. Default Tier-1 `SLICEBC\x01` Precompiled Boa `CodeBlock` CAS & Zero-Copy Framing (`0.02 us - 0.21 us` Instantiation)

- **The Problem Eliminated:**
  1. Wrapping bundled JS inside a JSON-serialized `BytecodeModule` (`SLICESNP`) required `serde_json::from_slice` to allocate and unescape a 30 KB - 130 KB `String` on every isolate run (`~229 microseconds`).
  2. Even with raw UTF-8 `SLICEBOA` framing, `boa_engine::Context::eval` had to run the full ECMAScript lexer, recursive-descent AST parser, `ScopeAnalyzer` identifier resolution, and `ByteCompiler` on `ULTRA_CORE_PRELUDE`, needed feature shards, `node:*` built-in scripts, and the user's bundled JS on every cold process launch.
- **Default `SLICEBC\x01` Precompiled `CodeBlock` Architecture ([`crates/slice-engine/src/vm/boacas.rs`](../../crates/slice-engine/src/vm/boacas.rs) & [`vendor/boa_engine/SLICE_PATCH.md`](../../vendor/boa_engine/SLICE_PATCH.md)):**
  - By default (`boacas = true`), [`compile_source_to_bytecode`](../../crates/slice-engine/src/vm/parser_and_compiler.rs) calls [`pack_boacas_container`](../../crates/slice-engine/src/vm/boacas.rs), which emits a **32-byte `BoaCasHeader` (`b"SLICEBC\x01"`)** containing:
    - `feature_flags: u16` (`BOACAS_FLAG_HAS_WORKER`, `BOACAS_FLAG_HAS_NEXT_TICK`, `BOACAS_FLAG_HAS_HTTP_BRIDGE`, `BOACAS_FLAG_HAS_SEMVER_FAST`, `BOACAS_FLAG_HAS_KV_SANDBOX`, `BOACAS_FLAG_NEEDS_LAZY_GETTERS`, `BOACAS_FLAG_NEEDS_SES_CHECK`, `BOACAS_FLAG_IS_RC_BUNDLE`, `BOACAS_FLAG_STARTS_WITH_BRACE`) + `shards_mask: u32`: Computed together in a **single $O(N)$ `aho_corasick::AhoCorasick` DFA pass** via [`detect_shards_and_boacas_flags`](../../crates/slice-engine/src/preludes/js_preludes.rs) inside [`compute_boacas_metadata`](../../crates/slice-engine/src/vm/boacas.rs) (eliminating 38 separate `.contains()` linear substring scans over bundled JS).
    - `rc_key: u64` (pre-extracted persistent realm cache fingerprint)
    - `precompiled_len: u32` (`SLCB\x01` binary `CodeBlock` payload) + `fallback_js_len: u32`
  - **Pre-Fused Prelude + JS Shards (`1..=18`, `29`) + `node:*` Built-Ins (`19..=28`) + `BUILTIN_SLICEBC_CACHE`:** At build time, `pack_boacas_container` fuses `ULTRA_CORE_PRELUDE`, all required runtime JS shards (`1..=18` and bit `29` in topological `SHARD_LOAD_ORDER`), and all statically referenced `node:*` built-in modules (`19..=28`) directly with the user script into a **single unified `Gc<CodeBlock>`**, serialized via [`boa_engine::Script::compile_to_slicebc`](../../vendor/boa_engine/src/script.rs). For dynamic or non-fused `require("node:*")` lookups at runtime, [`eval_lazy_builtin_module`](../../crates/slice-engine/src/preludes/node_builtins.rs) caches precompiled `SLCB\x01` `CodeBlock` bytes per static snippet pointer in `BUILTIN_SLICEBC_CACHE` so each built-in module is parsed and byte-compiled at most once per process.
  - **Lazy Stringified Cold Modules:** Unreachable or cold-method `node_modules` factories deferred by [`collect_eager_module_indices`](../../crates/slice-cas/src/linker/lazy_and_inline.rs) (`__slice_modules[id] = "..."`) are skipped by `is_in_lazy_string_module_line` during shard scanning and remain inert string constants inside `SLCB\x01` until dynamically required at runtime.
  - **Zero-Parse Runtime Execution:** At runtime, [`SliceIsolate::exec_boacas_vm`](../../crates/slice-engine/src/isolate/exec_boa.rs) creates a bare `boa_engine::Context` (`create_bare_boa_realm`), registers only the required native Rust host functions in a single pass, deserializes the `Gc<CodeBlock>` directly from the `mmap` slice via [`boa_engine::Script::from_slicebc_bytes`](../../vendor/boa_engine/src/script.rs), and executes it on the VM - eliminating **100% of runtime JS lexing, AST parsing, scope analysis, and bytecode compilation** on cold start (see **[`tests/reports/latest.md`](../../tests/reports/latest.md)** for measured cold and warm latencies).
  - **Legacy `SLICEBOA` Source-in-CAS Fallback (`--no-boacas`):** If `--no-boacas` (or `// @slice-boacas: false` / `SLICE_BOACAS=0` / `[engine] boacas = false`) is set, `compile_source_to_bytecode` emits the 8-byte `b"SLICEBOA"` header followed by raw UTF-8 transpiled JS.

## 2. Pre-Warmed `Boa` Context Pool (`BOA_CONTEXT_POOL`), `__slice_rc` Persistent Realm Cache, & Sharded Preludes

### 2.1 Pre-Warmed `WarmBoaRealm` Pool ([`crates/slice-engine/src/runtime/boa_realm.rs`](../../crates/slice-engine/src/runtime/boa_realm.rs))
1. Maintains a thread-local pool of pre-initialized `WarmBoaRealm` instances (`SliceIsolate::prewarm_boa_pool(count)`), wrapped in `std::mem::ManuallyDrop<Vec<WarmBoaRealm>>` so thread exit on Windows never runs `boa_engine::Context::drop` after `boa_gc`'s TLS collector has already torn down.
2. Wraps executed scripts inside a lexical block (`{\n<js_code>\n}`) in [`exec_boa_full_es_vm`](../../crates/slice-engine/src/isolate/exec_boa.rs) so top-level `const`, `let`, and `class` declarations are scoped to that invocation and never collide when the warm context is reused across requests in `slice serve` or `slice run --warm`.
3. Routes `console.log` directly through a native Rust `__slice_console_log` host function writing straight into thread-local `BOA_STDOUT`.

### 2.2 Persistent Realm Module Cache (`__slice_rc`), Precompiled `__slice_drain_wu`, & `BOA_DIRTY_SUBSYSTEMS` Teardown
- [`bundle_entrypoint_with_deps`](../../crates/slice-cas/src/bundler/graph_bundler.rs) emits a 16-hex-char BLAKE3 fingerprint header (`//__SLICE_RC:<16_hex_chars>`) and caches evaluated `node_modules` exports (`__slice_cache`) plus the compiled entrypoint closure in `globalThis.__slice_rc`.
- On warm hits (`slice serve` or `slice run --warm`), [`WarmBoaRealm::loaded_bundles`](../../crates/slice-engine/src/runtime/boa_realm.rs) stores the compiled `boa_engine::JsObject` entrypoint function handle and invokes `fn_obj.call(...)` directly in Rust with **0 JS parser passes** and **0 `node_modules` CJS factory re-evaluations**.
- [`WarmBoaRealm::drain_wu_fn`](../../crates/slice-engine/src/runtime/boa_realm.rs) caches the precompiled `globalThis.__slice_drain_wu` function handle so [`SliceIsolate::drain_wait_until_tasks`](../../crates/slice-engine/src/isolate/http_and_ws.rs) drains background `ctx.waitUntil(...)` callbacks via direct `JsObject::call` without invoking `Context::eval` (`boa_parser` + `ByteCompiler`) on every HTTP request (see **[`tests/reports/latest.md`](../../tests/reports/latest.md)** for `slice serve` Tier-0 and Tier-1 keep-alive throughput).
- [`BOA_DIRTY_SUBSYSTEMS`](../../crates/slice-engine/src/runtime/boa_realm.rs) tracks a single-byte bitmask (`DIRTY_EVENT_LOOP`, `DIRTY_ALS`, `DIRTY_FETCH_MOCK`, `DIRTY_WEBSOCKET`, `DIRTY_SOCKETS`, `DIRTY_WORKERS`, `DIRTY_WASM`) so isolate teardown in [`teardown_boa_compartment_thread_locals`](../../crates/slice-engine/src/isolate/exec_boa.rs) and [`clear_event_loop_state`](../../crates/slice-engine/src/runtime/event_loop.rs) skips clearing subsystems that were never touched during the isolate turn.

### 2.3 Compile-Time Minified 32-Bit `shards_mask` Surgical Preludes (`00_ultra_core.js` + JS Shards `01..19` + Pre-Fused `node:*` Bits `19..=28`)

## 3. Native Rust Fast-Path Intrinsics (`url_and_usp`, `SHA-NI`, Asymmetric Crypto, `DEFLATE`/`Gzip`, `AsyncLocalStorage`, & In-Memory VFS Slab)

Implemented in [`crates/slice-engine/src/intrinsics/`](../../crates/slice-engine/src/intrinsics/mod.rs), [`crates/slice-engine/src/runtime/boa_realm.rs`](../../crates/slice-engine/src/runtime/boa_realm.rs), and [`crates/slice-engine/src/bindings/`](../../crates/slice-engine/src/bindings/mod.rs):

0. **Native Rust WHATWG `URL` & `URLSearchParams` Primitives ([`crates/slice-engine/src/intrinsics/url_and_usp.rs`](../../crates/slice-engine/src/intrinsics/url_and_usp.rs)):**
   - Provides [`parse_whatwg_url`](../../crates/slice-engine/src/intrinsics/url_and_usp.rs), [`can_parse_whatwg_url`](../../crates/slice-engine/src/intrinsics/url_and_usp.rs), [`normalize_url_pathname`](../../crates/slice-engine/src/intrinsics/url_and_usp.rs), [`usp_encode_component`](../../crates/slice-engine/src/intrinsics/url_and_usp.rs), [`usp_decode_component`](../../crates/slice-engine/src/intrinsics/url_and_usp.rs), and [`usp_parse_query`](../../crates/slice-engine/src/intrinsics/url_and_usp.rs), exposed to Shard 1 via `__slice_url_can_parse`, `__slice_usp_encode`, and `__slice_usp_decode`.
1. **Hardware `SHA-NI` Block Compression ([`Sha256State::compress_block_sha_ni`](../../crates/slice-engine/src/intrinsics/hash_and_hmac.rs)):**
   - Uses Intel/AMD `SHA-NI` instructions (`_mm_sha256rnds2_epu32`, `_mm_sha256msg1_epu32`, `_mm_sha256msg2_epu32`) with cached `AtomicU8` runtime feature detection (`sha,sse4.1,ssse3`) and automatic fallback to [`Sha256State::compress_block_soft`](../../crates/slice-engine/src/intrinsics/hash_and_hmac.rs).
2. **Native `ring` + `x25519-dalek` + FIPS-180-4 WebCrypto & `node:crypto` Suite with Asymmetric `Ed25519` / `X25519` / `ECDSA` / `RSA` & Tenant-Scoped Key Handle Cache ([`asymmetric_and_keys.rs`](../../crates/slice-engine/src/intrinsics/asymmetric_and_keys.rs), [`symmetric_and_kdf.rs`](../../crates/slice-engine/src/intrinsics/symmetric_and_kdf.rs), [`bindings/crypto.rs`](../../crates/slice-engine/src/bindings/crypto.rs)):**
   - Direct `JsArrayBuffer` / `JsUint8Array` zero-copy Rust host functions (`__slice_crypto_sha256`, `__slice_crypto_hmac_sha256`, `__slice_crypto_digest`, `__slice_crypto_hmac_sign`, `__slice_crypto_key_register`, `__slice_crypto_cipher`, `__slice_crypto_asym_keygen`, `__slice_crypto_asym_import`, `__slice_crypto_asym_sign`, `__slice_crypto_asym_verify`, `__slice_crypto_ecdh`, `__slice_crypto_kdf`, `__slice_base64_encode`, `__slice_base64_decode`).
   - Supports symmetric `AES-GCM` / `AES-CBC`, runtime asymmetric key generation (`Ed25519`, RFC 7748 `X25519`, and `ECDSA` `P-256` / `P-384`), PKCS#8 / PKCS#1 / SPKI / JWK / raw import & export, `Ed25519` / `ECDSA` / imported `2048`-`8192`-bit `RSA` (`RSASSA-PKCS1-v1_5` & `RSA-PSS` over `SHA-256`/`SHA-384`/`SHA-512`) signing & verification, and constant-time RFC 7748 `X25519` Diffie-Hellman key agreement (`crypto.diffieHellman` & `subtle.deriveBits`/`deriveKey`), while failing closed on unbounded runtime RSA/DSA prime generation.
   - Pre-expanded `ring::aead::LessSafeKey`, `ring::hmac::Key`, `AesExpandedKey`, `Ed25519` keypairs, `ECDSA` (`P-256`/`P-384`) keys, `RSA` key material, and `X25519` keys are cached in thread-local `CRYPTO_KEY_HANDLE_TABLE` (`CachedCryptoKeyMaterial`) scoped by `BOA_ACTIVE_TENANT` so repeated cryptographic operations skip key schedule/DER parsing while preventing cross-tenant handle access.
   - KDF operations (`PBKDF2`, `HKDF`, `scrypt`) charge proportional CPU fuel against `BOA_FUEL_BUDGET` (`consume_crypto_kdf_fuel`), deterministically trapping hostile iteration/cost parameters with `SandboxViolation::CpuFuelExhausted`.
3. **Self-Contained RFC 1951 (`deflate-raw`), RFC 1950 (`deflate`), & RFC 1952 (`gzip`) Compression Engine:**
   - Implemented in [`zlib_compress_bytes`](../../crates/slice-engine/src/intrinsics/compression.rs) and [`zlib_decompress_bytes`](../../crates/slice-engine/src/intrinsics/compression.rs) with LZ77 32 KB sliding-window compression, Stored/Fixed/Dynamic Huffman decompression, Adler-32, and CRC-32 validation, powering both WinterTC `CompressionStream` / `DecompressionStream` and `node:zlib` with zero external crate dependencies.
4. **Zero-Overhead `SliceJobExecutor` for `node:async_hooks` (`AsyncLocalStorage` & `AsyncResource`):**
   - Implemented in [`SliceJobExecutor`](../../crates/slice-engine/src/runtime/boa_realm.rs) and [`event_loop.rs`](../../crates/slice-engine/src/runtime/event_loop.rs): when `BOA_ALS_ACTIVE` is `false`, promise microtasks execute with zero snapshot overhead; when `AsyncLocalStorage` is active, `SliceJobExecutor` and the event loop capture and restore `BOA_ALS_SNAP` across every `await`, `.then()`, `Promise.all`, `setTimeout`, `setImmediate`, `queueMicrotask`, `process.nextTick`, and `fetch` boundary.
5. **Zero-Regex Native Rust SemVer & Utility Scanners:**
   - Implemented in [`semver_parse_strict_xyz`](../../crates/slice-engine/src/intrinsics/fast_parsers.rs), [`semver_coerce_xyz`](../../crates/slice-engine/src/intrinsics/fast_parsers.rs), and [`semver_satisfies_xyz`](../../crates/slice-engine/src/intrinsics/fast_parsers.rs) (~150 ns per check).
6. **Thread-Local Binary-Safe In-Memory VFS Slab Cache (`BOA_VFS_CACHE` & `BOA_VFS_DIRS`):**
   - Ephemeral files created during an isolate run (`writeFileSync`, `appendFileSync`, `mkdirSync`) are stored as raw `Vec<u8>` byte slabs in thread-local memory (`FxHashMap<String, Vec<u8>>`) and served in nanoseconds on subsequent `statSync` (with real OS `mtimeMs`), `readdirSync`, and binary/UTF-8 `readFileSync` calls, while falling back transparently to `std::fs` for pre-existing host files.
7. **Lazy On-Demand Host Binding Registration by Category ([`crates/slice-engine/src/bindings/mod.rs`](../../crates/slice-engine/src/bindings/mod.rs)):**
   - Cold `create_warm_boa_realm()` initialization registers only the ultra-core host functions (`__slice_console_log`, `__slice_map_error_stack`, `__slice_load_builtin`, `__slice_lazy_prelude`, timers, env, SHA-256, Base64, UTF-8), while specialized host bindings (`register_http_bridge_host_functions`, `register_kv_and_sandbox_host_functions`, `register_semver_and_fast_intrinsics_host_functions`, `register_wintertc_phase_n3_host_functions`, `register_async_hooks_host_functions`) are registered lazily only when their corresponding shard or built-in module is loaded.
8. **Vendored `boa_engine` Monomorphic Inline Caching (`InlineCache::get_fast`), Direct ECMA-404 `JSON` Fast Paths, & `SLICEBC\x01` `SourceMap` Stack Traces:**
   - **Zero-Borrow Monomorphic Inline Cache ([`vendor/boa_engine/src/vm/inline_cache/mod.rs`](../../vendor/boa_engine/src/vm/inline_cache/mod.rs)):** Caches `(mono_shape_id: Cell<u64>, mono_slot: Cell<Slot>)` keyed by monotonic `Shape::id()` directly on each [`InlineCache`](../../vendor/boa_engine/src/vm/inline_cache/mod.rs) entry. On monomorphic own-property `GetPropertyByName` / `SetPropertyByName` hits, [`InlineCache::get_fast`](../../vendor/boa_engine/src/vm/inline_cache/mod.rs) returns the property storage slot in $O(1)$ without borrowing `GcRefCell` or upgrading `WeakGc` shape pointers, while seamlessly transitioning through 4-way polymorphic caching (`PIC_CAPACITY = 4`) and megamorphic fallback.
   - **Direct Rust `JSON::parse_ecma404` & `Json::try_fast_stringify` Fast Paths ([`vendor/boa_engine/src/builtins/json/mod.rs`](../../vendor/boa_engine/src/builtins/json/mod.rs)):** `JSON::parse_ecma404` runs an iterative ECMA-404 state-machine parser (`MAX_DEPTH = 2048`) over `Latin1` and `Utf16` inputs with 8-byte SWAR unescaped string scanning, exact integer accumulation + `fast-float2` float parsing, and per-depth `SharedShape` / `ShapeChain` prediction so homogeneous arrays of JSON objects construct directly with populated monomorphic `Shape` slots. Complementarily, `Json::try_fast_stringify` serializes ordinary `JsObject`s and dense `Array`s (`DenseI32`, `DenseF64`, `DenseElement`) into a single `Vec<u8>` buffer using `Shape::with_property_keys`, 8-byte SWAR ASCII scanning, and `ryu_js` number formatting when no `replacer` or `space` argument is supplied.
   - **Lazy Multi-Frame Source-Map Stack Translation ([`crates/slice-cas/src/bundler/source_map.rs`](../../crates/slice-cas/src/bundler/source_map.rs) & [`vendor/boa_engine/src/script.rs`](../../vendor/boa_engine/src/script.rs)):** `SLICEBC\x01` serializes bytecode-to-line `SourceMap` entries inside `encode_codeblock` / `decode_codeblock`, and `Error.prototype.stack` lazily invokes `__slice_map_error_stack` to translate bundled frames via embedded `// #slice-source:` markers back to `file.ts:line:col` with `0.00 ns` overhead when `.stack` is not read.
   - **Chrome DevTools / Perfetto Execution Tracer ([`SliceIsolate::export_chrome_trace_json`](../../crates/slice-engine/src/isolate/mod.rs)):** `slice run --trace=<out.json>` (or `SLICE_TRACE=<out.json>`) emits a standard Chrome Trace Event Format (`ph: "X"`) JSON timeline capturing `isolate.instantiate`, `isolate.execute`, `state.checkpoint`, `state.restore`, and `sandbox.eval` spans.

## 4. Tier-0 (`SLICESNP`) and Tier-2 Unboxed 64-Bit Numeric Register Compiler & VM ([`numeric_vm.rs`](../../crates/slice-engine/src/vm/numeric_vm.rs))

- **Zero Name Heuristics:** Every JS/TS function (`Stmt::FuncDecl`, `Expr::ArrowFunc`, and function expressions) is analyzed structurally by [`try_compile_numeric_func`](../../crates/slice-engine/src/vm/numeric_vm.rs) regardless of function or parameter names.
- **Unboxed 32-Register Execution (`[f64; 32]`):** Pure numeric functions compile into 8-byte/16-byte [`NumericOp`](../../crates/slice-engine/src/vm/numeric_vm.rs) instructions (`LoadConst`, `Move`, `BinaryReg`, `BinaryImm`, `UnaryReg`, `MathIntrinsic`, `Jump`, `JumpIfFalse`, `CallSelf1`, `CallSelf2`, `LinearRecurrence2`, `Return`). Execution inside [`NumericFunc::execute`](../../crates/slice-engine/src/vm/numeric_vm.rs) operates entirely on unboxed `f64` and `i64`/`i32` bitwise values on the CPU stack (`256 bytes`, fitting in 4 CPU L1 cache lines) with **0 heap allocations** and **0 `FxHashMap` variable lookups**.
- **Structural Linear Recurrence Lowering ([`detect_linear_recurrence_ast`](../../crates/slice-engine/src/vm/numeric_vm.rs)):** Recognizes any 1-parameter self-recursive function matching `if (param <= 1) return ...; return c1 * f(param - 1) + c2 * f(param - 2);` (including unweighted Fibonacci-style and weighted Pell/Lucas-style recurrences under any identifier name) and lowers it to `NumericOp::LinearRecurrence2`, reducing $O(2^n)$ call trees to an $O(n)$ 2-register IEEE-754 `f64` loop over exact integer inputs (`0 <= n <= 78`) while cleanly falling back when out-of-domain arguments occur.
- **Amortized Fuel Metering:** Checks `(local_steps & 255) == 0` every 256 register instructions (and at every recursive call and loop recurrence), guaranteeing deterministic `SandboxViolation::CpuFuelExhausted` preemption on infinite numeric loops with `< 0.4%` branch overhead.
